# 설정 항목·기능 추가

설정 팝업은 **왼쪽 세로 탭 = 카테고리**, **오른쪽 = 고른 카테고리의 항목만** 보이는 구조다.
사용자가 탭을 골라 관련 기능만 모인 화면을 보게 한다. 모든 설정을 한 목록에 늘어놓지 않는다.

## 규칙

1. **카테고리부터 정한다.** 새 항목·기능은 기존 카테고리 중 주제가 맞는 탭에 넣는다. 맞는 탭이 없으면 **새 탭(카테고리)을 추가**한다.
2. **한 탭에는 관련 기능만.** 다른 주제의 항목을 "자리가 있어서" 끼워 넣지 않는다. 기존 탭의 주제가 흐려지면 탭을 나눈다.
3. **카테고리는 한 곳에서만 정의한다.** id·탭 라벨·순서는 `src/settings.ts`의 `SETTING_CATEGORIES` 배열이 정한다. 항목의 `section`은 그 id를 가리킨다. 배열에 없는 id를 쓰면 `settings.test.ts`가 실패해야 한다.
4. **값은 스키마로 추가한다.** `SETTINGS`에 항목을 넣으면 컨트롤이 자동으로 그려진다. 적용은 `src/main.ts`의 `applySetting`에서 한다. 코드에 값을 하드코딩하지 않는다 (CLAUDE.md 빌드 절).
5. **스키마로 못 그리는 UI는 카테고리 커스텀 패널로.** 목록·버튼·미리보기(예: 테마 목록과 가져오기)는 그 카테고리 탭 안의 패널로 붙인다. 커스텀 패널도 규칙 2를 따른다.
6. **팝업 공통 동작은 유지한다.** 바꾼 값은 바로 적용·저장(저장 버튼 없음), 항목별 기본값 되돌리기, "모두 기본값으로", 팝업 밖(단축키 등)에서 바뀐 값도 컨트롤에 반영.

## 카테고리 표

탭을 추가하거나 항목을 옮기면 이 표도 고친다.

| id | 탭 라벨 | 담는 것 | 상태 |
|----|---------|---------|------|
| `view` | 보기 | 본문 최대 폭, 상태바 글자 수(단어·글자·공백 제외·끔) | 있음 |
| `edit` | 편집 | 소스 글자 크기, 소스 줄바꿈, 파일을 열 때(보기/소스) | 있음 (Phase 2) |
| `theme` | 테마 | 테마 선택, `system`용 라이트·다크 쌍, 전환 시간 + 커스텀 패널 테마 목록·가져오기(`src/theme-panel.ts`)·추천 테마 팝업(`src/recommended-dialog.ts`) | 있음 (S-1~S-4) |
| `nav` | 탐색 | 제목 이동 시 위쪽 여백, 최근 파일 개수 | 있음 |
| `file` | 파일 | 초안 백업 간격 (앞으로: 인코딩 기본값·EOL) | 있음 (Phase 2) |

## 절차

1. 카테고리 결정 — 위 표에서 고르거나 새 탭을 정한다. 새 탭이면 `SETTING_CATEGORIES`에 넣고 순서를 정한다(자주 쓰는 것 위).
2. `SETTINGS`에 항목 추가 — `label`은 짧게, 설명은 `hint`로. 숫자는 `min`·`max`·`step`·`unit`, 선택은 `options`.
3. `applySetting`에 적용 분기 추가. 시작 시 첫 적용에서도 맞게 동작하는지 확인.
4. `settings.test.ts` — 정규화(범위·선택지)와 카테고리 id 존재 테스트가 통과하는지. 새 규칙이 있으면 테스트 추가.
5. 미리보기로 확인 — `npm run dev` → `http://localhost:1422/`에서 `Ctrl+,` → 탭 전환, 값 변경 즉시 적용, 기본값 되돌리기.
6. 위 카테고리 표와 `README.md` "설정" 절(항목·기본값·범위 표)을 갱신한다.
