## Design space

| Axis | Options / range | Fixed? | Why |
|------|-----------------|--------|-----|

| **마크다운 방언** | GFM(표·작업 목록·취소선·자동 링크) + 각주 + front matter + CJK-friendly 강조 | **고정** | 한국어 문서 필수 (brief R24) |
| **상대 이미지 경로** | 문서 폴더 기준 해석 | **고정** | 뷰어의 기본 가치. 없으면 "깨진 이미지" 뷰어 |

Constraints (must hold for every variant):

- Pillars: 깔끔함(크롬 최소) · 신뢰(바이트 보존·데이터 무손실) · 즉시성(더블클릭 → 1초 내 렌더)
- Scope: 단일 문서 열기·읽기·편집·저장의 수직 슬라이스 하나. 노트 앱(볼트·백링크·동기화) 아님
- Tech / content limits: Windows 10/11, WebView2 Evergreen 전제(brief W17). 스택은 `ideas/20260929-stack.md` 판정을 따름
- Do not touch: `samples/raw/` 픽스처(바이트 단위), 기존 위젯 프로젝트 툴체인 관례

## Variants

각 안은 **한 줄 + 핵심 규칙 3개 이내 + 저비용 판정 기준 + 리스크**. 완성 스펙이 아니다. 아래 안은 모두 고정 축(파일 연결·바이트 보존·UI 기조·GFM·상대 이미지)을 포함한다.

| # | One-liner | Core rules | Cheap check (어떻게 빨리 판단하나) | Risk | Constraint pass? |
|---|-----------|------------|-------------------------------------|------|------------------|
| V1 | **리더 퍼스트** — 더블클릭하면 깔끔하게 렌더되고, 필요하면 소스 모드로 고쳐 저장하는 뷰어 | ① 렌더 뷰가 기본, `Ctrl+/`로 소스 편집(CodeMirror 6 plain) 전환 ② TOC 사이드바 + 다크 모드 + 코드 하이라이트(hljs) ③ 외부 변경 시 dirty 아니면 조용히 리로드, dirty면 배너 | `samples/showcase.md` 더블클릭 → 1초 내 렌더 · `samples/raw/*` 열고 저장 → `git status` 깨끗 · 두 번째 파일 더블클릭 → 새 창 | 낮음. 소스 모드가 "편집"의 전부라 Typora 감각과 거리 있음. 탭·트리 없음 | pass |
| V2 | **Typora-lite 분할 편집기** — V1 + 소스\|미리보기 분할과 스크롤 동기, 탭, 폴더 트리, 수식·다이어그램 | ① 분할 뷰(`data-line` 기반 스크롤 동기, brief R1·R2) ② 탭 + 폴더 트리 + TOC(동시 표시) ③ KaTeX·Mermaid는 펜스 감지 시 지연 로드 | V1 체크 + 편집 중 미리보기 지연 < 100 ms(2,000줄) · 트리에서 파일 전환 시 탭 유지 · `$$`·```mermaid 렌더 | 중간. 스크롤 동기·탭 상태·트리 감시가 MVP 크기를 2배로 키움. 분할은 "문서 폭 절반"이라 Typora 감각과 다름(brief T24) | pass |
| V3 | **인라인 하이브리드** — Typora처럼 렌더된 문서 위에서 바로 편집(캐럿 든 줄·블록만 소스 노출), 탭 | ① CM6 데코레이션 2층(인라인 마크 숨김 ViewPlugin + 표·이미지·수식 block 위젯 StateField, `ideas/20260929-editor-engine.md`) ② 소스 모드 전환 유지 ③ 바이트 보존은 소스가 진실인 CM6 위에 줄별 EOL 맵으로 달성 | V1 체크 + 한글 IME로 `**굵게**`·백틱·표 셀·위젯 앞 입력 시 조합 깨짐 없음 · 무편집 저장 바이트 불변 · 한 줄만 고쳤을 때 diff가 그 줄에만 | 높음. 조합 중 데코 재빌드 금지(brief E10·G9)·WebView2 호스트 계층 IME 이슈(S14)·블록 위젯 자체 구현(G10)·2 MB급 데코 성능(E11) 실측 필요. **Typora와 가장 닮은 안**. 로드맵 Phase 5, `exp/live-preview` 브랜치 | pass (엔진 판정 `ADOPT*` + Phase 0 IME 스파이크 ⑧ 통과 시) |

- 에이전트는 **변형 생성 + 제약 검사**까지만 한다. "어느 것이 더 좋은가"는 판정하지 않는다.
- V3는 Typora와 의도적으로 닮은 안이다 (모방 여부 투명화).
- 비용 참고(판정 아님): 연구 기준으로 V1은 렌더러·파일 계층·설치기 세 덩어리, V2는 여기에 에디터·동기화·탭·트리, V3는 V1에 엔진 도입·IME 실측이 얹힌다. 로드맵은 어느 안을 골라도 Phase 0–1이 같도록 짰다 ([`docs/roadmap.md`](../../roadmap.md)).
