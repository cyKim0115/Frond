- Verdict: `DEFER`

## Proposal (user)

- 로드맵 4-6 "(검토) highlight.js → Shiki(JS 엔진, fine-grained 5~10개 언어, dual theme) 교체" — TextMate 문법이라 VS Code와 같은 색이 나온다는 장점. 2026-10-06 사용자 위임(단계마다 진행)으로 에이전트가 측정해 판정한다

## Context

- Goal of this pass: 지금 구조(highlight.js core + 언어 지연 로드, 색은 테마 토큰 `--color-prettylights-*`)를 바꿀 값이 있는지 숫자로 본다
- Constraints: 분할 뷰 미리보기 갱신 < 100 ms(로드맵 3-3 완료 조건), 첫 렌더 시간을 늘리지 않는다, 사용자 테마(색 토큰 JSON)가 코드 색도 바꿔야 한다, 설치기·exe 크기

측정(2026-10-06, Node 24, esbuild 번들 — 같은 10개 언어 ts·js·json·bash·python·rust·csharp·yaml·css·html, Shiki는 github-light·dark 두 테마 + JS 정규식 엔진):

| | Shiki 4.5.0 | highlight.js 11.12.0 |
|---|---|---|
| 번들 (min / gzip) | 886 KB / 143 KB | 67 KB / 21 KB |
| 초기화 | 50 ms | 8 ms |
| TS 300줄 한 번 강조 | **81.7 ms** | **3.2 ms** |
| 결과 HTML | 94 KB (색 인라인, 두 테마 변수) | 36 KB (클래스) |
| 언어 | 고른 것만(fine-grained) | 190여 개를 처음 만날 때 하나씩 지연 로드 |

## Scores

| Axis | Result | Evidence |
|------|--------|----------|
| Feasibility | Pass | `shiki/core` + `engine/javascript`로 CSP(`script-src 'self'`, WASM 없음) 안에서 돈다 |
| Direction fit | Partial | 색 정확도(TSX·중첩 문법)는 낫다. 대신 테마 색이 Shiki 테마 JSON에 묶여 사용자 테마 토큰(`--color-prettylights-*`)과 따로 놀고, dual theme은 지금도 토큰으로 된다 |
| Efficiency | Fail | 강조가 25배 느려 코드가 많은 2,000줄 문서의 분할 뷰 갱신 예산(100 ms)을 혼자 넘는다. 번들 13배. 큰 문서는 지금처럼 강조를 생략해야 하는 범위가 넓어진다 |

## Alternatives considered

| Alternative | Pros | Cons | Better when |
|-------------|------|------|-------------|
| Shiki 교체 (제안) | VS Code와 같은 색·문법 정확도 | 느림·무거움·테마 토큰과 분리 | 문서가 코드 위주이고 편집 중 미리보기를 안 쓸 때 |
| **highlight.js 유지 (현행)** | 빠름·가벼움·190개 언어 지연 로드·사용자 테마가 코드 색까지 | TSX·Vue 등 중첩 문법 정확도가 낮다 | 지금 |
| 내보내기(4-4)에만 Shiki | 보기·편집은 빠르게, 공유본만 정확한 색 | 화면과 내보낸 파일의 색이 달라진다 | 내보내기 색 불만이 생기면 |

## Decision

- Verdict: `DEFER`
- What we will do now: highlight.js를 그대로 쓴다. 언어 지연 로드·테마 토큰 색·큰 문서 생략 규칙 유지
- What we will not do: Shiki 의존성 추가, 강조 결과 HTML 형식 변경
- Modified approach: —
