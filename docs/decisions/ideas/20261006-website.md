## Proposal (user)

- 2026-10-06 "fork처럼 배포하는 페이지를 만들고 싶어. 또 깃북으로도 사용하는 페이지를 만들고 싶어. 방법만 리서치하여 커서용 핸드오프 문서를 남겨놔줘. 클라우드 플레어를 사용하는것과 같은 개인적 작업은 커서에서 진행할 예정"
- 같은 날 "어떤 요소들이 들어갈지 만들어보면돼. 우리 프로그램의 사용 장면들이 들어가면 좋을 것 같아. 다른 툴들의 사이트들도 리서치해서 의사결정해줘"
- 같은 날 "클라우드 플레어로 도메인 사기 전까지 모양만 만들어보는걸로 하자. 아니면 무료 도메인 방법을 서치해서 하던가" · "나의 도움이 없이 작업가능한 부분을 계획으로 정리" · "홈페이지 문서 작성할 계획을 세워줘. 오늘할일로 남길거야"

## Context

- "Fork"는 Git 클라이언트 fork.dev다(앞선 유료화 조사에서 사용자가 말한 "Fork 방식"과 같은 대상). 홈 한 장 + OS별 직링크 + 릴리스 노트 + `/buy`, 문서·개인정보처리방침은 없다
- 사용자는 GitBook 조직 cyKim(무료, 체험 2026-08-11 종료)에서 사이트 4개를 운영하고, 그중 3개가 저장소 `docs/site`를 GitHub → GitBook 방향 Git Sync로 싣는다(`cykim.gitbook.io/<이름>`). 같은 날 다른 세션이 Frond도 같은 방식으로 시작했다(`.gitbook.yaml`·`gitbook-docs.yaml`·[`gitbook-site.md`](../../gitbook-site.md))
- 배포 순서는 이미 정해졌다: Store MSIX 먼저(R-1~R-4), GitHub Releases·winget은 R-5. Store 제출에는 개인정보처리방침 URL이 필요하다
- 조사 근거 노트 4개: 다른 툴 사이트 13곳 실측, 문서 플랫폼(GitBook·Starlight·VitePress 등 + Pagefind 한국어 검색 실측), Cloudflare 배포·도메인·다운로드, 사용 장면·미디어

## Decisions

| # | 항목 | Verdict | 정한 것 | 이유 |

| W1 | 사이트 구성 | `ADOPT` | **제품 페이지**(자체 도메인, Cloudflare) + **사용 설명서**(GitBook) 두 개. 앱·README·사이트는 설명서를 `<도메인>/docs` 고정 주소(302)로 가리킨다 | 사용자가 둘을 따로 원했다. GitBook 무료는 커스텀 도메인·하위 경로가 없고(Essential 연 $780, `/docs` 하위 경로는 Ultimate 연 $2,988), 고정 주소면 설명서를 옮겨도 링크가 산다 |
| W2 | 제품 페이지 스택 | `ADOPT` | **Astro 7 정적**, 저장소 `website/`(GitBook 원고 `docs/site/`와 헷갈리지 않게 `site/`를 피함). SSR 어댑터·Starlight 없음 | 이미지 최적화(AVIF·WebP)·컴포넌트·JS 0. Astro·Cloudflare 공식 가이드가 정적 출력은 어댑터 없이 `assets.directory`만 쓴다고 한다. 1인 운영은 홈 한 장 구조(fork.dev·Kanri·Yaak)로 충분 |
| W3 | 사용 설명서 | `ADOPT_WITH_CHANGES` | **GitBook Free + Git Sync**(`docs/site/`, GitHub → GitBook, 편집 잠금) — 사용자 선택·기존 관례. 원고는 옮기기 쉽게 쓴다(블록 방침은 `gitbook-site.md` U-2) | 0원·관리 0, 사용자의 다른 프로젝트 3개와 같다. 조사자의 1순위는 Starlight였다(아래 W3-alt) |

| W4 | 호스팅 | `ADOPT` | **Cloudflare Workers 정적 자산**(`main` 없음) + Workers Builds(루트 `website`, 감시 `website/*`, main = 운영, 다른 브랜치 = 미리보기) | Pages 문서가 "Start new projects with Workers"라고 한다. 정적 자산 요청은 무료·무제한, 빌드 월 3,000분. 비교: Vercel Hobby는 "판매 광고"도 상업으로 봐 금지, Netlify 무료는 크레딧을 넘기면 계정 전체가 멈춤, GitHub Pages는 상업 이용 제한 문구 |
| W5 | 도메인 | `ADOPT` (사용자 구매) | 사용자가 Cloudflare Registrar에서 산다. 그 전에는 **로컬에서만** 만든다(공개가 먼저 필요하면 `workers.dev` 임시). 후보는 `website-launch.md` §8 | 원가 판매·네임서버 자동. `.kr`은 Cloudflare에서 못 산다. `frond.app`·`.dev`·`.com`·`.io`는 이미 남의 것 |

| W6 | 다운로드 동선 | `ADOPT` | 상태별 카드(준비 중 → Store 배지 → 직접 설치 → winget). 버전·크기·SHA256은 **빌드 때 GitHub API**(`digest`). 직접 설치 뒤 감사 페이지(SmartScreen·기본 앱 안내). `/download/windows` 302는 README용 | 손으로 고친 버전은 늦는다(fork.dev 홈 2.21.1, CDN 2.23.1). winget은 리디렉터 금지(`Validation-Indirect-URL`). 조사한 13곳 모두 SmartScreen 안내가 없었다 |

GIF·HTML 앱 모형·이미지 속 글자 금지. 설명서 그림·Store 스크린샷과 같은 원본 | 스크립트로 다시 찍을 수 있어 묵은 스크린샷(fork.dev 2020~2021 화면) 문제가 없다. 2200×1600 PNG는 Store 규격(PNG, 1366×768 이상)을 그대로 만족 |

## Scores

| Axis | Result | Evidence |
|------|--------|----------|
| Feasibility | Pass | `wrangler deploy --dry-run`·`wrangler dev`가 로그인 없이 동작(`/docs` 302·404 페이지 실측). 브라우저 미리보기(`?sample=`)가 제목 표시줄·탭까지 그린다(`index.html`). Astro 7.3.5·wrangler 4.147.0, Node 24.18 |

| Efficiency | Pass | 비용은 도메인 값(연 약 $10~15)뿐. 공개 상태는 `config.ts` 값으로 바꾸고 다시 빌드 |
