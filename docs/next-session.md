### 2026-10-06 작업 — 기본 테마 세이지 차콜·탭 모양 (사용자 요청)

- 내장 라이트·다크 = **미니멀 화이트 세이지 차콜**과 그 다크 짝(`src/theme/palette.ts` `sageCharcoalLight`·`sageCharcoalDark`). 예전 GitHub 색은 추천 테마 **GitHub 라이트·다크**로 옮겼고, 사용자 테마의 빈 토큰은 계속 GitHub 기본 팔레트로 채운다(이미 만든 테마 색이 안 바뀐다). `style.css` 셸 대체값도 같이 바꾸고 테스트가 같음을 지킨다
- 탭 띠: 안 고른 탭은 어두운 면(라이트는 선 색을 깐 세이지 회색, 다크는 본문보다 어두운 그림자 쪽) — 뒤에 꽂힌 갈피. 고른 탭은 본문 색 + 테두리로 아래 문서와 이어지고, 띠 아래 1px 선을 고른 탭만 끊는다. 색은 테마 토큰에서 `color-mix`로 만들어 사용자 테마도 따른다
- 확인: vitest·tsc, 헤드리스 Edge로 라이트·다크 탭 띠 캡처
- **탭 끌기 버그**(사용자 제보): 다른 탭을 누르면 버튼을 떼도 탭이 커서를 따라 자리를 바꿨다. 원인 — 누르면 활성화하며 탭 띠를 통째로 다시 그려
  누른 요소가 문서에서 떨어지고, 브라우저가 mousedown을 띠(`#tabs`)로 보내 제목 표시줄(`titlebar.ts`)이 빈 곳 누르기로 보고
  `startDragging`(창 이동 루프)을 시작 → pointerup을 앱이 못 받아 끌기가 남았다(헤드리스 Edge로 재현: mousedown 대상 = `#tabs`).
  고침 — `tabs.ts` render가 탭 요소를 id로 재사용하고 순서가 다를 때만 옮긴다. 버튼이 떨어진 채 움직이면(`buttons` 0) 끌기를 끝낸다
- **끌기 연출**: 끄는 탭은 커서를 따라오고(그림자, 위로) 이웃 탭이 한 칸 미끄러져 비킨다. 놓으면 새 자리로 미끄러져 들어간다(FLIP, 160 ms, 동작 줄이기 설정이면 없음).
  확인: `tabs.test.ts` 3건(요소 재사용·누른 탭 연결 유지·버튼 뗀 뒤 끌기 해제), 헤드리스 Edge 실제 마우스 입력으로 누르기→버튼 없이 움직이기(끌기 안 붙음)·끌어서 옮기기 캡처(라이트·다크)
- 사용자 실기 피드백 2건 고침: ① 놓을 때 원래 자리로 갔다가 미끄러져 보임 — transition을 켠 채 transform을 지워 되돌아가는 전환이 먼저 시작되고, 새 자리를 그 값이 섞인 채 재서 FLIP 시작점이 원래 자리가 됐다 → transition을 먼저 끄고 지운 뒤 잰다. 놓은 자리(pointerup)로 한 번 더 맞춘다
  ② 맨 앞·맨 뒤로 못 옮김 — 끄는 탭이 띠 끝에서 멈추는데 '가운데끼리' 비교라 끝 탭 가운데와 같아질 뿐 넘지 못했다 → 끄는 탭 앞 모서리가 이웃 가운데를 넘으면 비킨다.
  확인: `tabs.test.ts` 양 끝 이동 1건, 헤드리스 Edge에서 놓은 뒤 매 프레임 위치(놓은 자리 → 새 자리로 한 방향, 원래 자리로 안 튐)·양 끝 이동
